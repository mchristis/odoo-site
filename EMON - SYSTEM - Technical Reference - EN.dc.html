01 / Information

Seeing is not switching.

Monitoring makes measurements available. Control needs a separate, explicitly authorised path. An outbound connection can still carry incoming commands.

02 / Dependencies

Local needs proof.

Local execution still depends on working hardware, trusted firmware, valid credentials, metering and power. Cloud independence must be tested across restarts and outages.

03 / Limits

No absolute guarantee.

Segregating control reduces specific risks. It cannot establish the absence of every hidden mechanism or remove compulsory grid protection.

Why Europe is asking.

The Dutch RDI found cybersecurity shortcomings in its 2023 inverter sample. This supports careful assessment of remote access and updates, not conclusions based on a vendor’s country of origin. S04 ↗ S05 ↗

Does disabling remote configuration close every control path?

No. Monitoring, remote configuration, flexibility services, local APIs, support access and software updates can use different permissions and connections. For a deployed EMON system, inventory each interface and test which remain reachable after a function is disabled. General inverter security guidance supports examining interfaces, access and updates separately. S05 ↗

What happens to commands when the cloud reconnects?

Proposed EMON rule: queue telemetry with timestamps, but discard expired control requests. Reconcile device state before accepting a new setpoint. Do not replay a stale relay command or old trading schedule. The command lifetime and clock-loss behaviour still need specification and testing.

Can a local controller remove the inverter manufacturer’s authority?

Not by itself. The inverter may retain an independent OEM connection, update route or service interface. Those routes require inventory, configuration review and testing. Compromised device firmware may also undermine a controller’s assumptions.

Location alone does not establish security. Credentials, firmware, device interfaces, protection functions and recovery procedures still require assessment. These models do not describe or rate any manufacturer. S05 ↗

Remote commands

A request needs limits.

Proposed EMON rule: record who requested the action, which device it targets, the allowed range and the expiry time. Check the device response locally. Monitoring permission alone should not grant switching authority.

Protection

Safety retains priority.

Proposed EMON requirement: optimisation cannot override battery constraints, mandatory grid protection or the approved circuit protection design. Establish that separation in the actual hardware and software.

What EMON must prove

The intended local-plus-cloud architecture needs evidence across normal operation, lost communications, reboot, software update and service withdrawal. The resilience lab turns those conditions into explicit acceptance tests. Explore the tests ↗
